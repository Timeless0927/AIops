# AIOps Console Next UI Design

## 设计目标

AIOps Console Next 是 SRE/AIOps 运维控制台。第一屏就是可操作的后台，
不是营销首页，也不是装饰性总览。

核心目标：

- 证据优先：事件、证据、时间线、审批、执行、审计在同一工作流内可见。
- 密集但清楚：桌面端支持复杂排障，移动端只保留关键审批和事件意识。
- Gateway-only：前端只呈现 Gateway 授权后的数据和动作。
- 责任链可见：用户能看清 agent 请求了什么、为什么请求、谁批准、Gateway 执行了什么。
- 中文优先：默认中文界面，并提供中英切换。

## 视觉方向

采用浅色密集运维台：

- 主背景：冷灰白。
- 页面区域：白色或浅灰，不使用大面积深色背景。
- 面板：细边框、少阴影、4-8px 圆角。
- 状态色只用于风险、执行状态和告警等级。
- 深色区域仅用于日志、命令、trace/raw payload 等局部内容。
- 不使用大 hero、渐变装饰、卡片堆叠、营销式大标题。

建议色板：

- 页面背景：`#F6F8FA`
- 面板背景：`#FFFFFF`
- 次级面板：`#EEF2F6`
- 主文字：`#202832`
- 次级文字：`#5D6876`
- 边框：`#D7DEE8`
- 主操作蓝：`#1F6FEB`
- 成功绿：`#238636`
- 告警橙：`#B7791F`
- 高危红：`#C2413A`
- 阻塞紫灰：`#6E56CF`

字体：

- UI 正文：系统 sans-serif。
- 数字、ID、hash、命令、日志：monospace。
- 标题不放大到营销页尺度，控制台标题保持紧凑。

## 全局布局

桌面端使用三层结构：

```text
┌─────────────────────────────────────────────────────────────┐
│ Top bar: 全局搜索 / 环境 / 语言 / 通知 / 当前用户             │
├───────────────┬─────────────────────────────────────────────┤
│ 左侧导航       │ 页面标题 + 工具条                            │
│               ├─────────────────────────────────────────────┤
│ Operations    │ 页面主体                                     │
│ Governance    │                                             │
│ Admin         │                                             │
└───────────────┴─────────────────────────────────────────────┘
```

左侧导航分组：

- Operations：事件、Agent Runs、审批
- Evidence：全局搜索、报告
- Governance：审计、策略
- Admin：用户、设置

Top bar 元素：

- 全局搜索：`搜索事件、运行、审批、审计...`
- 当前环境：`prod` / `staging` / `dev`
- Gateway 状态：`实时` / `降级` / `离线`
- 语言切换：`中文 | EN`
- 通知入口
- 当前用户菜单

## 中英切换

默认语言是中文。

语言切换控件放在 Top bar，使用紧凑 segmented control：

```text
[ 中文 | EN ]
```

行为：

- 默认中文。
- 用户切换后持久化偏好。
- 已登录用户优先保存到用户偏好；未登录或接口不可用时可用浏览器本地偏好。
- 登录页也显示语言切换。
- 切换语言不改变当前 route、筛选、选中的事件、选中的审批或未提交表单内容。
- 所有导航、按钮、表单标签、状态文案、错误提示、空状态、确认弹窗支持中英双语。
- 事件标题、用户输入、日志内容、命令、ID、hash、trace id、外部系统返回原文不自动翻译。
- 审计记录中的历史文案按写入时的原始内容展示；界面标签可切换语言。

中文按钮文案示例：

- `开始诊断`
- `创建运行`
- `保存更改`
- `批准并执行`
- `拒绝请求`
- `终止运行`
- `阻止新审批`
- `打开审计链`
- `回滚上一版本`

英文按钮文案示例：

- `Start investigation`
- `Create run`
- `Save changes`
- `Approve and execute`
- `Reject request`
- `Terminate run`
- `Block new approvals`
- `Open audit chain`
- `Rollback previous version`

## 按钮体系

主按钮：

- 开始诊断 / Start investigation
- 创建运行 / Create run
- 保存更改 / Save changes
- 批准并执行 / Approve and execute
- 发布报告 / Publish report

次按钮：

- 刷新 / Refresh
- 重试 / Retry
- 查看证据 / View evidence
- 打开审计链 / Open audit chain
- 对比更改 / Compare changes
- 回滚上一版本 / Rollback previous version

危险按钮必须具体，不使用“确认”这类泛化文案：

- 终止运行 / Terminate run
- 阻止新审批 / Block new approvals
- 禁用用户 / Disable user
- 拒绝请求 / Reject request
- 标记需要回滚 / Mark rollback required
- 删除聊天消息 / Delete chat messages

禁用按钮必须显示原因：

- `无法审批：你不是合格审批人`
- `无法执行：需要审批`
- `无法保存：没有更改`

## 页面层级

每个页面固定四层：

1. Page header：标题、资源 ID、状态、关键动作。
2. Filter / action bar：搜索、筛选、时间范围、刷新、创建。
3. Main work area：表格、三栏工作台、详情面板。
4. Context / audit strip：最近事件、权限原因、责任链引用。

## 事件列表

元素：

- 搜索框
- 筛选：状态、等级、集群、命名空间、服务、团队、风险、时间范围
- 表格列：等级、状态、事件、服务、集群/命名空间、负责团队、最近运行、审批、最近出现
- 行动作：打开、开始运行、查看报告、打开审计

状态：

- 新建
- 诊断中
- 等待审批
- 执行中
- 需要回滚
- 已解决

## 事件详情

事件详情是三栏工作台：

```text
┌─────────────────────────────────────────────────────────────┐
│ 事件头部：标题 / 状态 / 风险 / 负责人 / 控制按钮              │
├───────────────┬───────────────────────────────┬─────────────┤
│ Chat / Run    │ Evidence workbench             │ Decision    │
│ - 提问        │ - 指标                         │ - 诊断结论  │
│ - /btw        │ - 日志                         │ - 建议动作  │
│ - 开始运行    │ - Trace                        │ - 审批状态  │
│ - 人工备注    │ - Kubernetes                   │ - 责任链    │
│               │ - 拓扑/变更/工具输出            │             │
└───────────────┴───────────────────────────────┴─────────────┘
```

头部按钮：

- 开始诊断
- 暂停运行
- 终止运行
- 人工接管
- 阻止新审批
- 解决事件
- 重新打开
- 创建报告

证据 tabs：

- 指标
- 日志
- Trace
- Kubernetes
- 拓扑
- 变更
- 工具输出

右栏优先级：

1. 诊断结论
2. 建议动作
3. 审批状态
4. 执行状态
5. 责任链摘要

## 状态设计

风险：

- 只读：蓝灰
- 低风险：绿
- 中风险：橙
- 高风险：红
- 阻塞：紫灰

状态不能只靠颜色，必须同时有文本和图标。

通用状态：

- 加载：skeleton，保持布局高度。
- 空：说明缺什么和下一步。
- 错误：显示 request id 和重试按钮。
- 无权限：403 和原因。
- 部分可用：显示成功部分和失败源。
- 已过期/冲突：禁用写操作，提示刷新。
